# 任务与共同经历：实时更新

> 答应过的事、一起经历过的事，**说完就记，不用等后台整理**。

---

## 1. 原来慢在哪

```
对话 →（等 30 分钟）→ janitor 抽事实 → 落库 → 下一轮才能用上
```

两个后果：

- 刚答应的事，这一拍就想不起来，要等半小时
- 「共同经历」在每轮配额里只占 1 条，还和别的分类抢位置，经常挤不进去

---

## 2. 现在怎么走

```
一条消息进来
   ├─ 词面命中「答应过的语气」→ 立刻写任务
   ├─ 词面命中「一起做过」    → 立刻写共同经历
   └─ 下一拍读上下文时，两者都已在里面
```

**不调 LLM**，只靠词面特征。宁可漏，不可误记。

| 触发词（任务） | 触发词（共同经历） |
|---|---|
| 我明天 / 我待会 / 回头我 / 我帮你 | 我们一起 / 咱们 / 你给我 / 我帮你 |
| 记得提醒我 / 别忘了 / 说好了 | 一起看 / 一起吃 / 陪我看 / 陪你 |
| 下次 / 改天 / 我这就 / 我马上 / 保证 | 你帮我 |

---

## 3. 任务和「悬着的事」不是一回事

| | 任务 | 悬着的事 |
|---|---|---|
| 是什么 | 答应过、还没做的**承诺** | 想弄明白、还没答案的**疑问** |
| 例子 | 「我明天提醒你交作业」 | 「那个游戏到底怎么玩」 |
| 存哪 | `open_loops` 表，`source='task'` | `open_loops` 表，`source` 为空 |
| 进 prompt | `# 你答应过、还没做的事` | `# 你心里还悬着的事` |
| 怎么关 | 用 `resolve` 标记完成 | 用 `resolve`（有答案）或 `drop`（不要答案了） |

混在一起的后果：她会把「我答应过你」和「我好奇」当成同一类东西，
于是要么催自己催得很烦，要么真的忘了答应过什么。

---

## 4. 共同经历给足了位置

```
统计：每轮上下文里各类事实的配额

共同经历  3   ← 从 1 提到 3，且排序时优先
身份      3
关系      3
喜好      2
经历      2
观点      1
```

SQL 里也改了排序：

```sql
ORDER BY (predicate='共同经历') DESC, id DESC
```

否则「共同经历」会被一堆新写的「身份」「喜好」挤到取不到。

---

## 5. 文件 ↔ 库

共同经历会出现在人物卡里，格式和别的事实一样：

```markdown
# 爸爸

- [f1] 身份：养我的那个人
- [f7] 共同经历：一起看了那个修自行车的视频
- [f9] 共同经历：熬到三点一起看直播
```

手改这些行同样有效（下一轮导入）。

## 6. 代码在哪

| 文件 | 作用 |
|---|---|
| `core/tasks.py` | 词面检测、写任务、写共同经历、统计 |
| `core/live.py` | `feed()` 里调用 `tasks.capture()` —— 实时 |
| `core/self.py` | `facts_here()` 配额与排序；`tasks_text()` 读任务 |
| `core/act.py` | 把任务拼进 act 的 prompt |
| `core/mind.py` | 把任务拼进 think 的上下文 |

想加自己的触发词，改 `core/tasks.py` 顶部的 `TASK_HINTS` / `SHARED_HINTS`。

## 7. 一个已知的坑（已修）

`actor_name` 原来被 `names.label()` 覆盖成「路人XXXX」，
因为那个函数是按微信 wxid 设计的——拿不到名字就编一个。

QQ 上报里**本来就有昵称和群名片**，被这个兜底冲掉了，
结果所有 QQ 消息都记成「路人」，人物卡全建错了人。

现在：通道上报的名字优先，拿不到才回落到名字表。
