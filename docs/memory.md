# 记忆

> **记忆的真身是 SQLite，`记忆/` 目录只是给人看的镜像。**
> 上下文里永远只放「这一刻用得上」的那一小块。

---

## 1. 三层

| 层 | 内容 | 何时进上下文 |
|---|---|---|
| 热 | 最近对话（每场景保留 40 条，注入 12～16 条） | 每拍 |
| 常驻 | 在场几个人的身份/关系/偏好事实（默认 8 条，v1 每人 15 条） | 每拍 |
| 冷 | 全部事件、事实、日记 | 她主动 `recall` 时才翻 |

自主模式下「翻不翻」由她决定；应答模式下每轮固定召回 `recall_limit` 条。

---

## 2. 库里有什么

`<profile.dir>/feiyu.db`，13 张表（`memory/schema.sql`）：

| 表 | 一句话 |
|---|---|
| `events` | 情景记忆：说过的、看到的、做过的。每条带 `importance`(1–10)、场景、时间 |
| `events_fts` | `events` 的全文索引（中文按 bigram 切） |
| `facts` | 语义记忆：关于某人的稳定认知（身份 / 经历 / 偏好 / 关系 / 观点） |
| `entities` | 实体：人、群、她自己的别名 |
| `relations` | 熟悉度（只涨）+ 好感（可升可降） |
| `self_state` | 她的状态：心情、精力、睡到几点、身份缓存、各种水位 |
| `reflections` | 日记与反思（每天一篇，写给自己） |
| `thoughts` | 念头池（自主模式的核心） |
| `open_loops` | 悬而未决的事（「他说的那个事我还没问」） |
| `search_pool` | 搜到但还没决定记不记的暂存 |
| `expressions` / `intents` | 预留，当前代码没用 |

召回打分（`memory/store.py: recall`）：

```
score = 0.45·cos + 0.20·bm25 + 0.20·recency + 0.15·importance  × 关系加成
```

> 注意：向量那一路**目前是空跑的**——`events.embedding` 从来没写过，
> 所以 0.45 那一项的权重恒为 0，实际生效的是 FTS + 实体 + 时间/重要度。
> 想接向量，写 `embedding` 字段并在 `recall()` 里把它传进来即可。

## 3. 文件镜像：`记忆/`

```
记忆/
├── index.md              人物索引与计数（程序生成，别手改）
├── 我是谁.md              L1 自我认知，每拍重读 ★
├── 人设卡.md              v1 的人格卡（L1 内核 + 反 AI 味硬规则）
├── 我自己的记忆.md        她自己的备忘，520 字注入上限
└── 我/
    ├── <人名>.md          一人一张：一行一条事实
    └── _示例.md           模板自带的虚构示例
```

### 同步规则

| 方向 | 时机 | 规则 |
|---|---|---|
| 库 → 文件 | 后台整理（默认 1800 秒） | 按人导出 `facts`，一行一条 |
| 文件 → 库 | 启动、整理时 | 只同步**新增和修改**；删行在下次导出水位前**不算遗忘** |
| 人 → 文件 | 随时 | 手改立即生效（下一拍/下一轮） |

事实行格式：

```markdown
- [f12] 经历：说好下周一起去爬山
```

- `[f12]` 是事实 id，新写的可以省略，程序会自己编号
- 分类只有五种：`经历 / 身份 / 偏好 / 关系 / 观点`

### 为什么「删行 ≠ 立刻遗忘」

早期版本把「文件里没有」当成「这条事实是假的」，于是程序还没导出时，
每次启动都在丢记忆。现在用导出水位兜住：**只有程序写出去之后又被你删掉的，
才算你的意思**。这个语义别改。

## 4. 遗忘与衰减

- 低于 importance 阈值的旧事件，30 天后**归档**（`archived=1`），不删除。
- 活跃念头超过 20 条，丢最弱最老的。
- 悬着的事最多 20 条，需要她（或你）主动 `resolve` / `drop`；
  相似的事按中文 bigram 重合度合并。
- 好感范围 -100～+100：被夸 +2、被敷衍 -0.5、被凶 -1.5（`core/relations.py`）。

**没有「一键清空记忆」这种动作。** 想重来就删库（会重建空库）：

```bash
rm data/feiyu.db*          # 注意：连同 -wal / -shm
```

## 5. 备份

只需要三个东西：

```
data/feiyu.db  (+ -wal / -shm)
记忆/
data/secrets/        # 渠道与 B 站凭据
```

停掉主循环再复制，或者用 SQLite 的 `VACUUM INTO` 做在线备份。

## 6. 多角色

`config.json` 的 `profiles` 下每个键是一个角色，各有 `dir`（库）、`memory`（镜像）、
`persona`（自我认知文件）与可选的 `channels` / `thresholds`。

```json
"profiles": {
  "阿鱼":  { "dir": "data", "memory": "记忆" },
  "另一个": { "dir": "profiles/另一个", "memory": "profiles/另一个/记忆" }
}
```

启动：`python run_wx.py --profile 另一个`。单例端口按序号错开（8790、8791…），
所以两个角色可以同时跑。面板右上角切的是「看谁」，不影响谁在跑。

## 7. 导入与冷启动

想给一个新角色一份「出厂设定」：

1. `python tools/init_persona.py` 建目录
2. 把她必须记得的事写进 `记忆/人设卡.md` 的 L1 内核（这部分每轮都进 prompt）
3. 把她认识的人写成 `记忆/我/<人名>.md`（一行一条，程序会反向导入库）
4. 别一开始就塞几千条事件——让它在对话里自己长出来，检索质量更好

> 导入别人的聊天记录当语料之前，先确认你有权处理那些内容。
> 这个项目不提供语料清洗工具，也不建议把真人对话直接灌进来。
