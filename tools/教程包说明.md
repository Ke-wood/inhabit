# 阿鱼 · 教程工具包

三个脚本。它们不给她加功能，是让她**看自己的设定、然后自己决定要不要改**。

思路是一样的：把一段「她一直在用、但从没被告知过的东西」摊开给她看，说明它是什么、能怎么改，然后让她自己拍板。改不改都行。

---

## 前提

1. 项目已经能跑起来（`start.bat` → `9` 能上线）
2. **建议先把主循环停掉** —— 不然她一边在你问、一边在被消息触发，回答会乱
   - 菜单按 `2 停止`；停不掉就去任务管理器结束 python 进程
3. 脚本放在项目的 `tools/` 目录下，从项目根运行

---

## 1. `loop_lesson.py` —— 让她自己清理「悬着的事」

**这是什么**

她有一个机制叫「悬着的事」：想弄明白但还没答案的问题会一直挂在头顶，每次「想」都先看到一遍。挂太久会变成反复盘问同一个问题。

这个脚本把列表摊给她看，告诉她两种处理方式：

- `resolve` —— 我想明白了，有答案了
- `drop` —— 我不想弄明白了，答案也不要了

两个都会让它从头顶消失。

**怎么跑**

```bash
python tools/loop_lesson.py 5      # 问 5 轮
```

**生效方式**

她选一条就立刻从库里的 `open_loops` 表关掉，下一轮「想」就看不到它了。

**注意**

- 她可以每轮都说「都留着」，这是正常的，说明这些事她真在意
- 脚本会明确提醒她「不确定别编答案」——编一个答案等于永远记着错的东西
- 同一个话题反复出现（措辞不同），系统会自动合并，不需要她处理

---

## 2. `identity_check.py` —— 让她确认自己的人设

**这是什么**

她的自我认知存在 `记忆/我是谁.md`，每次「想」之前都会读一遍。它决定了：

- 她怎么看自己（多大、什么脾气）
- 别人问「你是谁」时她心里的底
- 她遇到事从什么立场出发

这个脚本告诉她「这是可以改的」，然后把当前内容给她看。

**怎么跑**

```bash
python tools/identity_check.py 2   # 问 2 轮（一般 1 轮就够）
```

**生效方式**

她改了就立刻写文件，**不需要重启**，下一轮「想」生效。

**注意**

- 她很可能选择不改，这是正常的
- 如果她写了一段你这不想要的（比如偏离了你原本的简单设定），直接改 `我是谁.md` 就行，或者跑这个脚本让她再想一次

---

## 3. `prompt_review.py` —— 逐段评审她收到的全部 prompt

**这是什么**

她每次「想」和「做」，都会收到几段固定的话：人设、说话的样子、怎么想、怎么做、自我记忆。这些她从来没看过正面。

这个脚本把五段逐段摊开，一段一次问她：

- 这段你怎么看
- 想不想改

**怎么跑**

```bash
python tools/prompt_review.py          # 五段全问
python tools/prompt_review.py 怎么想    # 只问某一段
```

**能不能改**

| 段 | 存在哪 | 她能改吗 |
|---|---|---|
| 人设 | `记忆/我是谁.md` | ✅ 直接写文件 |
| 自我记忆 | `记忆/我自己的记忆.md` | ✅ 直接写文件 |
| 说话的样子 | `core/persona.py` 的 `STYLE_RULES` | ❌ 只记录意见 |
| 怎么想 | `core/mind.py` 的 `THINK_SYSTEM` | ❌ 只记录意见 |
| 怎么做 | `core/act.py` 的 `ACT_SYSTEM` | ❌ 只记录意见 |

改不了的那三段，她的意见会存到：

```
data/prompt_review.jsonl
```

一行一条，格式：

```json
{"segment": "说话的样子", "opinion": "她的看法", "new_text": "她建议的完整新版本"}
```

你可以照着改代码里的常量。

**注意**

- 「怎么做」那 2445 字她大概率说「选项太多像菜单」——那是工具说明，不是她能定的
- 输出偶尔会被截断，脚本里做了补全，实在解析不了会跳过

---

## 共同注意事项

**这些是「问她」，不是「命令她」**

三个脚本都设计成她可以拒绝。如果她一直说「不改」「都留着」，那是真实的选择，别当成 bug。

**改了她也记得**

她改人设、改记忆、关悬案，都会在 `data/feiyu.db` 的 `events` 表里留一条 `kind='action'` 的记录。以后她回忆起来会看到「我改过自己的自我认知」这种事。

**跑之前备份一下**

```bash
copy data\feiyu.db data\feiyu.backup.db
```

虽然脚本只做增删标记、不删数据，但保险。

**跑完记得重启主循环**

如果之前停了服务，改完再启动一次。

---

## 一句话总结

这三个脚本解决的是同一个问题：**她的设定大多是别人写好的，她只负责执行。** 教程轮就是让她有机会说「这个我认」或者「这个不像我」。
